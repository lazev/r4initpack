PROBLEMA: Autoload sem sanitizacao permite path traversal teorico
SEVERIDADE: MEDIO
ARQUIVO: php/r4iniend.php, linhas 31-34
STATUS: Nao corrigido

------------------------------------------------------------------------

O QUE ACONTECE:

O autoloader registrado faz:

    spl_autoload_register(function($className) {
        $className = strtolower($className);
        require ROOT . $className .'/'. $className .'.class.php';
    });

O $className e apenas convertido para lowercase, sem remover
caracteres como ../ ou validar que e um nome de classe valido.

Em teoria, se um atacante conseguisse influenciar o nome de uma
classe sendo instanciada, poderia incluir arquivos de outros
diretorios.

------------------------------------------------------------------------

COMO CORRIGIR:

Sanitizar o nome da classe para permitir apenas letras e numeros:

    spl_autoload_register(function($className) {
        $className = strtolower($className);
        if(!preg_match('/^[a-z0-9]+$/', $className)) return;
        $file = ROOT . $className .'/'. $className .'.class.php';
        if(file_exists($file)) require $file;
    });

Mudancas:
1. Rejeita nomes com caracteres especiais (../ barras, etc)
2. Verifica se o arquivo existe antes de incluir
3. Nao lanca erro se o arquivo nao existir (permite que outros
   autoloaders tentem, como o do Composer)

------------------------------------------------------------------------

RISCO REAL:

Medio-baixo. O nome de classe normalmente vem do codigo PHP (new Users,
new ValidFields), nao de input do usuario. Mas em cenarios com
desserializacao de objetos ou frameworks que instanciam classes
dinamicamente, o risco aumenta.
