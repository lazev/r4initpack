PROBLEMA: Modulo exemplo (initPack) induz interpolacao direta de variaveis no SQL
SEVERIDADE: ALTO
ARQUIVO: utils/initPack/src/users/users.class.php, linhas 113, 127, 196
STATUS: Nao corrigido

------------------------------------------------------------------------

O QUE ACONTECE:

O modulo users que serve como MODELO para todos os novos modulos
(criados com "r4 initmodule") usa interpolacao de variaveis no SQL:

    $old = $db->select("select * from users where id = $id limit 1");

    $retdb = $db->sql("update users set [fields] where id = $id", $new);

    $ret = $db->sql("update users set dtDel = now() where id = $id");

Nesses casos especificos o $id e castado para (int), entao esta seguro.
Mas o PADRAO que o desenvolvedor vai copiar e o de interpolar
variaveis diretamente na string SQL.

Quando criar modulos com campos nao-numericos, vai naturalmente fazer:

    $db->select("select * from users where slug = '$slug'");

E ai esta o SQL injection.

------------------------------------------------------------------------

COMO CORRIGIR:

Trocar a interpolacao direta pelo uso de :parametros em todo o modulo
exemplo, para que o padrao copiado seja seguro:

ANTES:
    $old = $db->select("
        select * from users where id = $id limit 1
    ");

DEPOIS:
    $old = $db->select("
        select * from users where id = ':id' limit 1
    ", ['id' => $id]);

ANTES:
    $retdb = $db->sql("
        update users set [fields] where id = $id
    ", $new);

DEPOIS:
    $new['id'] = $id;
    $retdb = $db->sql("
        update users set [fields] where id = ':id'
    ", $new);

Fazer o mesmo para delete e undel, trocando:
    where id = $id
    where id in ($strId)
por versoes parametrizadas.

------------------------------------------------------------------------

POR QUE E IMPORTANTE:

O initPack e a primeira coisa que o desenvolvedor ve ao usar o R4.
Se o exemplo usa interpolacao, todos os modulos do projeto vao usar.
Se o exemplo usa :parametros, o desenvolvedor segue o padrao seguro
sem nem pensar em SQL injection.
