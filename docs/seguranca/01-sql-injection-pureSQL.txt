PROBLEMA: SQL Injection no metodo pureSQL - valores substituidos sem aspas
SEVERIDADE: CRITICO
ARQUIVO: php/db.class.php, linha 209
STATUS: Nao corrigido (pode quebrar codigo existente)

------------------------------------------------------------------------

O QUE ACONTECE:

O metodo pureSQL faz substituicao simples de :parametro pelo valor:

    $sqlQuery = str_replace(':'. $key, $this->real_escape_string($val), $sqlQuery);

O real_escape_string escapa caracteres como aspas e barras, mas o valor
e colocado SEM aspas na query. Isso so e seguro quando o desenvolvedor
coloca aspas manualmente no SQL:

    where id = ':id'        <-- seguro (com aspas)
    where id = :id          <-- VULNERAVEL (sem aspas)
    order by :orderBy       <-- VULNERAVEL (ORDER BY nao usa aspas)
    limit :limit            <-- VULNERAVEL (LIMIT nao usa aspas)

------------------------------------------------------------------------

EXEMPLO DE EXPLORACAO:

No users.class.php, a listagem faz:

    $db->select("
        select id, user, nome from users
        where excluido = 0
        order by :orderBy
        limit :limit
    ", $bindFilter);

O orderBy vem do input do usuario ($listParams['orderBy']).
Um atacante pode enviar:

    orderBy = "CASE WHEN (SELECT pass FROM users WHERE user='admin') LIKE 'a%' THEN nome ELSE user END"

O real_escape_string NAO bloqueia isso porque nao tem caracteres
escapaveis. Resultado: blind SQL injection para exfiltrar dados.

------------------------------------------------------------------------

CUIDADO AO CORRIGIR:

Esta e a correcao mais delicada porque:

1. Muitos projetos ja usam pureSQL/select com :parametros sem aspas
2. Adicionar aspas automaticamente quebraria queries com ORDER BY, LIMIT,
   nomes de coluna, e valores numericos em comparacoes
3. Trocar para prepared statements reais (mysqli prepare/bind) mudaria
   o comportamento fundamental do metodo

------------------------------------------------------------------------

POSSIVEIS ABORDAGENS:

A) Criar um metodo separado (ex: safeBind) que use prepared statements
   reais, e marcar pureSQL como deprecated gradualmente.

B) Adicionar whitelist para campos de ORDER BY e LIMIT nos modulos,
   validando que o valor recebido e um nome de coluna permitido antes
   de passar para a query. Exemplo:

    $allowedOrder = ['nome', 'email', 'id', 'dtCad'];
    $orderBy = in_array($listParams['orderBy'], $allowedOrder)
        ? $listParams['orderBy']
        : 'nome';

C) No minimo, documentar claramente que :parametro em contextos sem
   aspas (ORDER BY, LIMIT, nomes de tabela) NAO e seguro e que o
   desenvolvedor deve validar esses valores antes de passar ao metodo.

------------------------------------------------------------------------

MODULO EXEMPLO AFETADO:

O users.class.php (initPack) que serve de modelo para novos modulos
usa o padrao vulneravel no listFilter. Qualquer modulo criado com
"r4 initmodule" herda esse padrao.
